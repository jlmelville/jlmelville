I think about dimensionality reduction a lot.

I wrote and maintain uwot, an implementation of UMAP in R and C++. If you’ve made a UMAP plot of single-cell data with Seurat, you’ve probably used it.

When I was trying to work out how UMAP differed from t‑SNE, I read the Python code and asked Leland McInnes about the bits I couldn’t follow. Much of what I wrote down ended up in the implementation appendix of the UMAP paper.

      How I measured this

      I generated four groups of points with a fixed seed. The exact calculation visits every pair. Barnes–Hut groups distant points in a tree. FFT interpolation collects their contributions on a grid. All three use the same positions and the same normalized t‑SNE repulsion.

      The reference is the Barnes–Hut tree with θ set to zero, checked against a direct sum. Timings cover one force calculation after warm-up, with the FFT workspace reused and the methods run in shuffled order. Relative force error is the length of the error vector divided by the length of the exact vector, after joining all the points’ arrows end to end. These timings describe this layout on this machine.       Software

      Run UMAP in R
      uwot fits embeddings, works with labels and projects new observations into an existing embedding.
      Find nearest neighbors
      rnndescent works with dense and sparse data. RcppHNSW brings hnswlib to R. Both can supply neighbors to uwot.
      Compare embeddings
      I use smallvis to change one thing at a time in R. For larger 2D embeddings, its C++ code can approximate the repulsive forces with FFT interpolation, a Barnes–Hut tree or a mutual tree. In Python I use drnb to compare methods on the same datasets. Try the force comparison.
      Test an embedding
      I get datasets like Fashion-MNIST from snedata and plot the 2D coordinates with vizier. With quadra I can check how many of each point’s original neighbors are still nearby.
      Optimize an objective
      mize implements unconstrained optimizers in R. Its sibling funconstrain gives me 35 test problems from Moré, Garbow and Hillstrom to try them on.
      Prepare a CRAN release
      I built revdeprunner around r-lib’s revdepcheck to smooth out a few rough edges in my own releases. I can see what needs building before I start checking the packages that depend on mine. It’s also my first entirely vibe-coded package.
